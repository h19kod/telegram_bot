# 05 — API Specification

The machine-readable contract is the OpenAPI 3 schema generated by drf-spectacular
(`/api/schema/`, Swagger UI at `/api/docs/` — disabled in production unless staff-authenticated).
This document defines the surfaces, conventions and endpoint inventory.

The schema is generated with zero warnings (`--validate --fail-on-warn`, enforced by
`tests/test_openapi.py`) and committed as `frontend/packages/shared/openapi.json`, from which
`make schema` generates the TypeScript types (`@sop/shared`: `paths`, `components`,
`operations`). Contract tests call the real endpoints and check every response against the
schema; a drift test fails when the committed schema is out of date. Every operation documents
the shared error envelope as `4XX` (`components.schemas.Error`). `/internal/v1` (bot service,
private network) is deliberately excluded from the published schema.

## 1. Surfaces and authentication

| Surface | Base path | Auth | Consumers |
|---------|-----------|------|-----------|
| Auth | `/api/v1/auth/` | — / JWT | Dashboard |
| Business (tenant) | `/api/v1/b/{business_id}/` | JWT + Membership + permission | Dashboard |
| Storefront | `/api/v1/store/{business_slug}/` | Customer token (from Mini App initData) | Mini App |
| Platform | `/api/v1/platform/` | JWT + `is_platform_admin` + 2FA | Platform console |
| Internal | `/internal/v1/` | Service HMAC (not routed by Nginx) | Bot service |
| WebSocket | `/ws/b/{business_id}/` | Single-use WS ticket | Dashboard |
| Health | `/healthz`, `/readyz` | — | Docker, monitoring |

### Dashboard tokens
- `POST /api/v1/auth/login` → `{access}` (JSON, 10 min) + `refresh` in `HttpOnly; Secure; SameSite=Strict; Path=/api/v1/auth/` cookie (14 days, rotated on every refresh, reuse → whole family revoked).
- The access token is kept in memory only (not localStorage).
- `POST /auth/refresh` requires the cookie **and** an `X-CSRF-Token` header (double-submit) since it is cookie-authenticated.

### Mini App customer token
- `POST /api/v1/store/{slug}/session {init_data}` → server validates initData (HMAC-SHA256 with key `HMAC_SHA256("WebAppData", bot_token)`, `auth_date` ≤ 24 h old, bot belongs to `slug`), upserts `Customer`, returns a customer JWT (1 h, claims: `customer_id`, `business_id`, `scope=store`).
- Every storefront call checks the token's `business_id` matches the slug.

### Internal service auth
Header `X-Service-Auth: v1:{timestamp}:{hmac_sha256(secret, method|path|timestamp|sha256(body))}`; ±60 s window; replay-protected by nonce cache in Redis.

## 2. Conventions

- JSON, `snake_case`, UTF-8. Money as integer minor units plus `currency` (e.g. `{"total": 12500, "currency": "IQD"}`); clients format.
- IDs are UUID strings; orders also expose `number`.
- Pagination: cursor-based for feeds (`?cursor=`), page-number for admin tables (`?page=&page_size=` max 100). Response: `{results, next, previous, count?}`.
- Filtering/search: `?status=pending&placed_after=2026-11-01&search=برغر&ordering=-placed_at` (django-filter, whitelisted fields only).
- Language: `Accept-Language: ar|en` selects translated fields & messages; bilingual fields are also returned raw for editing endpoints.
- Idempotency: `Idempotency-Key` header **required** on checkout and order transitions; optional on other POSTs.
- Concurrency: transitions send `expected_version`; conflict → `409`.
- Rate limits: per user/customer/IP via DRF throttles in Redis; `429` with `Retry-After`.

### Error format

```json
{
  "error": {
    "code": "product_unavailable",
    "message": "هذا المنتج غير متوفر حالياً",
    "details": {"product_id": "…"},
    "request_id": "01JC…"
  }
}
```

Validation errors: `code: "validation_error"`, `details: {field: [messages]}`.
Status codes: 400 validation, 401 unauthenticated, 403 authenticated-but-forbidden (own tenant), 404 not found **or other tenant**, 409 conflict/stale, 422 business-rule violation (e.g. `below_minimum_order`, `outside_working_hours`, `plan_limit_exceeded`), 429 throttled.
